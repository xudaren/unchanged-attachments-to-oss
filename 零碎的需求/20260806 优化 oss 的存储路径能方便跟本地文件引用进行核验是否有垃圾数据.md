# OSS 对象与 Obsidian 引用核验

## 结论

Obsidian 文档没有适合作为外部存储关联键的稳定内置唯一标识。文档路径会因重命名和移动改变；自行写入 frontmatter UUID 也不能准确表达同一文档内的重复引用和跨文档复制引用。

Object Key 不承载文档路径或文档 ID，只负责稳定寻址。Vault 中实际存在的 `oss://{objectKey}` 是引用关系的唯一事实源。定期核验通过 Vault 引用集合与 OSS 对象集合做集合差完成，不能只比较数量。

## 存储路径

继续使用随机且不可变的 Object Key：

```text
{objectKeyPrefix}/{crypto.randomUUID()}.{ext}
```

不使用文档路径、文档名称或附件原名组成 Object Key，避免文档移动、重命名后 OSS 路径语义失效，也避免为了保持路径一致而复制和删除远端对象。

## 核验算法

用户通过命令手动发起核验：

```text
Vault 引用集合 R
  = 所有 Markdown 与 Canvas 中的有效 oss:// Object Key
  + pendingUploads 中仍在 uploading / uploaded 状态的 Object Key

OSS 对象集合 O
  = ListObjectsV2(objectKeyPrefix)，完整处理分页

正常对象 = O ∩ R
疑似垃圾 = O - R
引用失效 = R - O
```

同一个 Object Key 被引用多次时，集合中只计算一个对象，同时单独记录引用次数用于报告。数量相等不代表内容匹配，因此核验结果必须按具体 Object Key 展示。

## 权限边界

- 设置保存时的凭证探针仍只对随机不存在的 Key 执行签名 GET，禁止调用 ListObjects。
- `ListObjects` 权限是核验功能的可选权限，只在用户主动执行核验命令时使用。
- 没有 `ListObjects` 权限时，上传、渲染和删除等原有功能不受影响；核验命令应提示需要增加指定前缀的只读枚举权限。
- 删除疑似垃圾对象仍需要 `DeleteObject` 权限。

## 交互与删除安全

1. 扫描完成后展示正常对象、疑似垃圾、引用失效、上传任务四类数量，并提供 Object Key 明细。
2. 默认只生成报告，不自动删除。
3. 疑似垃圾对象默认不选中，由用户逐项选择。
4. 最近 24 小时创建的对象进入保护期，不允许在核验界面删除。
5. 删除前重新扫描 Vault 引用；已被重新引用的 Object Key 自动跳过。
6. 删除操作逐项隔离失败；OSS 明确返回 404 视为对象已不存在。
7. `.oss-plugin-probe/` 等插件内部保留路径不作为附件垃圾展示。

## 验收标准

- OSS 对象超过 1000 个时仍能完整分页核验。
- 同一 Object Key 在一个或多个文档中重复引用不会被误报为垃圾。
- OSS 有对象而 Vault 无引用时报告为疑似垃圾。
- Vault 有引用而 OSS 无对象时报告为引用失效。
- 上传中或已上传待提交引用的 pending Object Key 不会被误报为垃圾。
- 扫描后、删除前新建引用的对象不会被删除。
- 缺少 ListObjects 权限时只影响核验功能，并给出可操作的权限提示。
