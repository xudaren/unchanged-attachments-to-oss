# OSS 附件按需加载

## 核验结论

- PDF 当前只在本地计算签名并渲染“打开”链接，未点击时不下载 PDF 数据，保持现状。
- 视频、音频当前在渲染时立即设置签名 `src`，浏览器可能自动请求元数据或部分内容，存在额外 OSS 流量。
- 图片当前在渲染后立即下载，长文档和 Canvas 中的不可见图片也可能产生流量。

## 实现规则

- PDF 仅生成签名链接，只在用户点击“打开”后由浏览器请求内容。
- 音频先渲染原生控件，但不设置 HTTPS `src`；首次指针或键盘播放交互时再注入签名 URL。`preload="none"` 只作补充，不作为零请求的唯一保证。
- 视频在进入视口附近时设置签名 `src` 和 `preload="metadata"`，允许浏览器发起 Range 请求读取元数据/首帧；视口外不挂载 HTTPS `src`。
- 图片使用 `IntersectionObserver` 在进入视口附近时才设置签名 `src`，附加 `loading="lazy"`。不支持 `IntersectionObserver` 的环境回退为立即加载。
- Reading View、Live Preview 和 Canvas 必须共用同一套加载策略，并保持节点 Object Key 校验和逐项错误隔离。

## 验收

- 未交互的音频 DOM 不含 HTTPS `src`；视口外视频不含 HTTPS `src`，进入预加载边界后可读取元数据/首帧。
- 视口外图片不挂载签名 `src`，进入预加载边界后才挂载。
- PDF 卡片未点击时只存在链接，不存在 `embed`/`iframe`。
